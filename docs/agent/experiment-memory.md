# Experiment Memory

この文書は、CodeEval 研究に関する重要な前提、決定、注意点を蓄積するためのメモである。

Codex に長期的な研究文脈を渡すための中心文書として使う。

## 研究目的

CodeEval の目的は、ローカルLLMがリバースエンジニアリング支援に使えるかを評価することである。

具体的には、既存 C++ ソースコードから設計文書を生成し、その設計文書から C++ コードを再生成し、テストによって妥当性を評価する。

## 重要な分離

CodeEval では、以下を明確に分離する。

- Codex が整備する実験基盤
- ローカルLLMが生成する設計文書
- ローカルLLMが生成する C++ コード
- 実験スクリプトが出力する結果
- 人間が解釈する研究メモ

この分離を崩すと、研究結果の信頼性が下がる。

## Codex の基本方針

Codex は、実装・保守・文書化を支援する。

Codex は、評価対象であるローカルLLMの代わりに、生成設計文書や生成 C++ コードを手動で作ってはいけない。

## v3 の位置づけ

v3 は、設計文書生成プロンプトを一般化する実験である。

v3 では、コード生成側の self-check は追加しない。

v3 の主な関心は、設計文書にどのような情報を含めると、後段の C++ 再生成が成功しやすいかである。

## v4 の位置づけ

v4 は、v3 の設計文書生成プロンプトを固定したうえで、コード生成側に self-check を追加する実験である。

v4 の主な関心は、self-check によって `compile_failed` や `code_generation_failed` が減るかどうかである。

## 評価で重視すること

評価では、単純な成功率だけでなく、失敗の種類を分けて見る。

特に以下を区別する。

- `pipeline_failed`
- `design_generation_failed`
- `code_generation_failed`
- `compile_failed`
- `test_failed`
- `passed`

## 運用メモ

実験結果は推測で補完しない。

失敗した結果も研究上の情報として残す。

長い実験の前には、dry-run または少数問題で動作確認する。
